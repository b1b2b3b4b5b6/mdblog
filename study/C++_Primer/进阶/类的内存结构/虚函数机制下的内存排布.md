## 内存排布
* 先将基类依次排布
    * 优先放置多态基类
* 含有virtual成员函数
    * 如果头部无预留虚函数表指针空间，则新增

## 成员函数调用流程（编译期决定）
### 非虚函数
* 非静态成员函数带有隐含形参`BASE * const this`, 在调用时，结合函数地址，对象地址（如果调用父类的成员函数，则需要编译器调整this指针至实际父类内存位置），其他实参完成调用
* 静态成员数无隐含形参`BASE * const this`
> 如果成员函数不解引用this，则通过指针强转成员函数也可以正常运行
### 虚函数
* 每种多态类都有自己的虚函数表（可以多个），写死在.rodata中，并将其地址写死在指向虚函数表的指针空间中
    * 如果是单继承，那只有一个虚函数表
    * 如果是多继承，则会有多个虚函数表，第一个虚函数表为主表，放置子类独有的虚函数
    * 如果父类有多个虚函数表，则子类也会有多个虚函数表
* 对于子类和父类来说，虚函数是通过虚函数表来找到函数地址
    * 如果调用父类的成员函数，this指针需要调整至实际父类内存位置
    * 通过虚函数表指针获得虚函数表
    * 相同的函数符号使用相同的表内偏移
    * 获得函数地址
* 后续步骤与非虚函数流程相同

### this指针调整
|                  场景                  | 虚函数实现 |       this 指针指向        |            是否有 thunk             |
| ------------------------------------- | ---------- | -------------------------- | ----------------------------------- |
| **单继承 + 未 override**              | 基类       | 派生类对象起始/基类对象起始 | 不需要                              |
| **单继承 + 已 override**              | 派生类     | 派生类对象起始/基类对象起始 | 不需要                              |
| **多继承（非第一基类）+ 未 override** | 基类       | **基类子对象**⚠️          | 无 thunk                            |
| **多继承（非第一基类）+ 已 override** | 派生类     | 派生类对象起始              | 有 thunk(编译时直接偏移)             |
| **单继承 + 虚继承**                   | 派生类     | 派生类对象起始              | 有 thunk(需要通过offset_to_top得到) |

**chunk机制**
```cpp
// 实际生成的 vtable (简化)
Base2::vtable_for_Derived:
[
    0: &Derived::func2_thunk  // 不是直接指向 Derived::func2！
]

// 编译器生成的 thunk
void Derived::func2_thunk() {
    // 调整 this 指针：this = this - 0x10
    asm("sub rdi, 0x10");  // rdi 寄存器存储 this (x86-64)
    
    // 跳转到真正的函数
    return Derived::func2();
}
```
为何chunk可以知道如何调整this指针：
- 派生类内存中，第二基类部分有自己的vptr和虚函数表
- 编译器为第二基类生成虚函数表时，知道第二基类相对于派生类头部的内存偏移值
